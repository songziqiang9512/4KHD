# 4KHD 原生图片浏览器适配执行计划

> 日期：2026-05-10
> 目标：使用成熟开源方案和现有 Apify 抓取资料，把 4KHD 做成稳定的原生图片浏览器，而不是网页套壳。

## 一、最终架构

应用主链路采用：

```text
Apify 数据索引
  -> 真实详情页 DOM 抽图
  -> Nuke 图片加载、缓存、取消、预取
  -> 原生三段式图片浏览 UI
```

职责边界：

- Apify：提供首页列表、分类、标题、封面、详情链接、页数、图数、推荐和广告结构线索。
- WKWebView：只负责打开真实详情页并从 DOM 里提取图片和分页链接，不承担可见 UI。
- Nuke / NukeUI：负责封面、缩略图、大图的加载、缓存、优先级、取消和预取。
- SwiftUI 原生 UI：负责三段式布局、快速切图、缩放、保存、翻页和状态展示。

## 二、不再走的路径

这些路径已经在 `docs/4khd-wrong-paths-memo-2026-05-01.md` 中记录，本阶段继续规避：

- 不直接把站点页面作为主界面。
- 不把单张图片 HTML 塞进 WebView 当成真实详情页。
- 不把 Apify 里的图片 URL 当成最终大图显示方案。
- 不在每次切图时重新打开同一个详情页。
- 不把 WebView 的截图当作最终保存文件。
- 不用简单 `onAppear` 哨兵无限触发翻页。

## 三、执行阶段

### 阶段 1：接入成熟图片管线

改造内容：

- 引入 Nuke / NukeUI。
- 替换当前手写的 `RemoteImageView`。
- 配置统一请求头：
  - `Referer: https://www.4khd.com/`
  - Chrome-like `User-Agent`
  - 图片 Accept header
- 建立加载优先级：
  - 当前右侧大图：最高
  - 底部缩略图：中等
  - 左侧封面：低

完成判断：

- 左侧封面、底部缩略图、右侧大图都进入同一图片加载管线。
- 切换详情时，旧图片请求不会继续抢占当前详情页资源。

状态：已完成。当前使用 Nuke core 统一加载图片，保留同一套 Referer、User-Agent、Accept 请求头，并为大图、缩略图、封面分配不同优先级。

### 阶段 2：WebView 降级为隐藏解析器

改造内容：

- `DetailImageResolverView` 不再把网站页面或注入查看层显示给用户。
- 真实打开详情页后，只返回：
  - 当前页图片 URL 列表
  - 详情分页 URL 列表
  - 推荐区和广告区边界信息
- 右侧大图显示改为原生图片视图。

完成判断：

- 右侧不会在加载期间闪出网站页面。
- 页面解析失败时显示明确的解析失败状态。
- 成功解析后，大图由原生视图显示。

状态：已完成。WKWebView 只作为 1x1 隐藏 DOM 解析器，右侧可见区域由原生图片画布接管。

### 阶段 3：调整网络调度和取消策略

改造内容：

- 启动时优先读取 Apify 列表数据。
- 列表封面低优先级加载。
- 用户选中图集后，立即解析当前详情页。
- 切换到另一个图集时：
  - 停止上一个详情页 WebView 加载。
  - 取消上一个详情页大图和缩略图任务。
  - 当前详情页首张大图优先。
- 当前页解析完成后，才预取相邻图片和下一页。

完成判断：

- 快速点选多个标题时，最终只显示最后一次选择的详情。
- 旧详情页不会在之后回写右侧 UI。

状态：已完成第一版。详情页回调会校验当前已加载槽位，切换图集会重置预解析页并停止详情图片预取。

### 阶段 4：统一自动翻页入口

改造内容：

- 缩略图滚到底和大图切到最后一张都调用同一个加载方法。
- 加载方法需要判断：
  - 是否还有下一页。
  - 是否已经加载过。
  - 是否正在加载。
  - 新页是否和旧页重复。

完成判断：

- 滚到底自动加载下一页。
- 切到最后一张自动加载下一页。
- 不重复追加第一页内容。
- 当前选中图片 index 不错乱。

状态：已完成第一版。缩略图滚动到底和大图向后跨过已加载范围都进入同一个 `ensureNextDetailPageLoaded`，并按 page URL 去重；本地 HTML 只允许作为第一页 fallback，避免 `/2` 被错误解析成第一页。

### 阶段 5：保存原图

改造内容：

- 保存逻辑不再依赖 WebView snapshot。
- 优先保存 Nuke 缓存中的原始图片数据。
- 缓存缺失时，用同一套带请求头的图片请求下载。
- 文件名使用图集 id 和图片序号。

完成判断：

- 保存结果是原图数据，不是当前屏幕截图。
- 保存失败时有明确提示。

状态：已完成。保存走 Nuke 的原始 data 加载链路，不再截取 WebView。

### 阶段 6：整理原生三段式 UI

改造内容：

- 左栏：栏目和内容类型过滤。
- 中栏：图集列表，显示封面、标题、图数、页数、推荐/广告标记。
- 右栏：大图优先，底部缩略图胶片条，顶部操作栏。
- 支持触控板缩放、上一张、下一张、保存。

完成判断：

- 首屏就是可用的图片浏览器。
- 右侧大图区域占最大空间。
- 站点页面不再参与可见 UI。

状态：已完成第一版。当前 UI 为左侧栏目、中间图集列表、右侧大图和底部胶片条；右侧支持上一张、下一张、触控板缩放和保存。

## 三点五、已补充的稳定性细节

- 下一页追加后会启动第二个隐藏解析器提前解析该页，避免翻到下一页第一张时才开始打开详情页。
- 选中位置距离当前已加载末尾 6 张以内时，会提前追加并预解析下一页，不必等到真正越界才开始请求。
- 当前图后面的若干张已知图片 URL 会低优先级预取到 Nuke 内存缓存。
- 下一页请求以 URL 集合去重，滚动触底和点击下一张不会重复追加同一页。
- 详情解析结果必须命中当前已加载的 page URL，旧图集或错误跳转结果不会写回当前 UI。

## 四、验证方式

每一阶段至少执行：

```bash
xcodebuild -scheme 4KHD -configuration Debug -destination 'platform=macOS' build
```

涉及 UI 或图片显示的阶段还需要启动应用验证：

- 左侧列表是否正常显示。
- 点选图集后右侧是否进入加载状态。
- 详情解析完成后右侧大图是否出现。
- 底部缩略图是否显示。
- 快速切换图集时是否只保留最后一次选择。
- 滚到底和切到最后一张是否触发下一页。

## 五、当前第一批落点

第一批代码改造只做必要主链路：

1. 接入 Nuke / NukeUI。
2. 替换 `RemoteImageView` 的实现。
3. 新增原生大图显示组件。
4. 把 `DetailImageResolverView` 改成隐藏解析器。
5. 编译并启动应用验证。
