# UI 改造备忘

日期：2026-05-17

## 核心目标

1. 工作区交互向 macOS Finder / Mail 靠拢。
2. 右侧详情区支持展开 / 折叠。
3. 工具栏搜索框旁边提供独立的详情区开关。
4. 详情区展开时，中栏自动避让并收缩到 2 列网格语义。
5. 详情区关闭时，中栏自动填充可用宽度。

## 关键风险

1. 详情区开合如果不是壳层状态，而是散在模块里，中栏联动一定会反复出问题。
2. 在线中栏是 SwiftUI 网格，本地中栏是 AppKit 网格，不能先追求“同一套实现”，要先保证“同一套行为”。
3. 本地网格列数逻辑在 AppKit layout 内部，详情区联动必须给 layout 一个外部列策略输入。

## 实施顺序

1. 在 Shell / Shared 建立详情区布局状态。
2. 在中栏 toolbar 搜索框旁边加入详情区开关。
3. `NavigationSplitView` 统一管理详情区显示 / 隐藏。
4. 在线中栏根据壳层状态切换为自适应填充或 2 列受限布局。
5. 本地 AppKit 网格根据壳层状态切换为自适应填充或 2 列受限布局。
6. 验证详情区展开 / 折叠时选择、滚动、缩略图、搜索和工具栏无回归。

## 当前决定

1. 第一阶段不强行抽统一网格组件。
2. 第一阶段优先抽共享的布局状态和详情区开关按钮。
3. 如果 SwiftUI 在详情区开合联动上不稳定，再只对壳层布局部分补 AppKit 桥接，不先全量下沉。
